# Plant Scan API

A Cloudflare Worker that holds the Gemini key, meters the free tier, and
verifies Play subscriptions. The app talks only to this.

Why it exists: a key passed to `flutter build` is embedded in the APK and can
be extracted from it, and a scan limit enforced on the device is bypassed by
clearing app data. Both problems disappear once the key and the counter live on
a server.

## Deploy

```bash
cd server
npm install
npx wrangler login

# Storage for the per-device counters.
npx wrangler kv namespace create QUOTA
# Paste the printed id into wrangler.toml.

# Secrets — never committed.
npx wrangler secret put GEMINI_API_KEY
npx wrangler secret put PLAY_SERVICE_ACCOUNT_EMAIL
npx wrangler secret put PLAY_PRIVATE_KEY

npx wrangler deploy
```

Set `ANDROID_PACKAGE_NAME` in `wrangler.toml` to your real application ID
before deploying, or subscription checks will fail.

The free Workers plan covers 100,000 requests a day, which at three scans per
user is far more than you will need for a long time.

## Local development

```bash
cp .dev.vars.example .dev.vars   # if you make one; otherwise create it
npx wrangler dev
```

`.dev.vars` holds the same keys as the secrets above, one per line as
`NAME=value`. It's gitignored.

Point the app at it with `--dart-define=BACKEND_URL=http://10.0.2.2:8787` from
an Android emulator (`10.0.2.2` is the host machine, `localhost` is the
emulator itself).

## Endpoints

Every request needs an `x-device-id` header — 16 to 128 characters, generated
once per install by the app.

| Method | Path | Does |
| --- | --- | --- |
| `GET` | `/v1/quota` | Current allowance, refreshing entitlement from Play if needed |
| `POST` | `/v1/identify` | `{image_base64, mime_type}` → identification + quota. 429 when out |
| `POST` | `/v1/ad-credit` | Grants the rewarded-ad bonus, once per day |
| `POST` | `/v1/subscription` | `{purchase_token, product_id}` → verifies with Google, grants access |

Quota replies look like:

```json
{
  "limit": 3,
  "remaining": 2,
  "ad_credit_available": true,
  "scans_per_ad": 2,
  "entitled": false,
  "entitled_until": null
}
```

`remaining` is `-1` for subscribers, meaning unlimited.

Smoke test after deploying:

```bash
curl -s https://plant-scan-api.YOUR-SUBDOMAIN.workers.dev/v1/quota \
  -H "x-device-id: 0123456789abcdef0123456789abcdef"
```

## Play subscription verification

`POST /v1/subscription` asks Google whether a purchase token is real. Setting
that up:

1. Google Cloud console → enable the **Google Play Android Developer API**.
2. Create a service account, then create a JSON key for it.
3. Play Console → Users and permissions → invite the service account email,
   granting **View financial data**.
4. Put the JSON's `client_email` into `PLAY_SERVICE_ACCOUNT_EMAIL` and its
   `private_key` into `PLAY_PRIVATE_KEY`, newlines and all.

Permissions take a few minutes to propagate; a fresh service account often
returns 401 for a while before it starts working.

A cancelled subscription keeps working until the period the user paid for runs
out, and a Play API outage never revokes access — an entitlement refresh that
fails leaves the last known state alone.

## Known limits

Counters live in KV, which is eventually consistent, so two scans fired in the
same instant can both read the same count and slip through. The cost is an
occasional extra Gemini call. Move to a Durable Object if that ever matters;
`QuotaStore` is the only thing that would change.

Device IDs are generated by the app, so reinstalling earns a fresh allowance.
Closing that means Play Integrity attestation or requiring sign-in, both of
which cost installs. It's a deliberate trade for an app with a three-scan free
tier — there is little worth farming here.
